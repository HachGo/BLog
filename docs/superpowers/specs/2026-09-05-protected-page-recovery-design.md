# 加密页面构建恢复与密码提示设计

## 目标

确保年度总结页面的构建无论成功或失败都会恢复 Markdown 原文，并在用户输入错误密码时给出明确、可重试的提示。

## 方案

新增一个 Node 构建编排脚本，依次执行加密脚本和 VitePress 构建。只要加密阶段已启动，编排脚本都会在 `finally` 中运行恢复脚本；构建失败仍返回原始失败状态，恢复失败则返回恢复失败状态。

`package.json` 的 `docs:build` 改为只调用该编排脚本，避免依赖 shell 的 `&&` 语义。该方案在 Windows、macOS 与 Linux 下使用同一套 Node 行为。

密码表单增加独立的错误状态。解密返回空值时，表单保持可见、清空密码输入值、聚焦输入框，并显示“密码错误，请重试。”；成功提交和新一次提交会清除该提示。

## 范围

- 修改构建命令与加密/恢复编排逻辑。
- 修改 `ProtectedContent` 的错误密码交互与样式。
- 使用 Node 原生测试覆盖失败构建后的恢复调用，以及错误密码提示状态。

不改变加密算法、密码存储策略、受保护页面范围或 GitHub Actions 的密码注入方式。

## 验收标准

1. 加密后的 VitePress 构建成功时，源 Markdown 与临时加密数据均被恢复/清理。
2. VitePress 构建失败时，恢复脚本仍会执行，且构建命令返回失败。
3. 输入错误密码时，用户可看到错误提示并立即重新输入。
4. 正确密码仍可完成解密。
